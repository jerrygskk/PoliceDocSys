# 依角色隱藏主功能 TAB 設計

日期：2026-07-29

## 目的

主視窗完整版共有 11 個 TAB。在 Windows 125% 顯示縮放與全域 14pt 字體下，所有 TAB 同時顯示會使 TAB 列過度擁擠。

本功能依目前登入角色隱藏無權限使用的 TAB，讓剩餘 TAB 自動向左遞補且不保留空位。這是介面精簡，不建立新的角色或權限系統；各功能既有的操作權限 guard 繼續生效。

## 非目標

- 不新增或重新命名角色。
- 不調整各 TAB 內部版面。
- 不刪除、銷毀或在角色切換時重建 TAB 物件。
- 不改變既有功能的操作權限。
- 不依角色製作三套不同版本的 HELP 或速查卡；共用內容仍須補充角色可見性與登入導向說明。
- 不隱藏首頁主選單的功能 icon。

「交辦單發文」及「敘獎發文」均屬一般業務功能，一般使用者必須看得到。

## TAB 顯示機制

### Profile 與角色各自負責的範圍

`AppProfile` 繼續決定目前產品版本實際包含哪些 TAB，例如完整版與獨立版的功能差異。角色可見矩陣只能作用於目前 Profile 已包含的 TAB，不得顯示 Profile 未提供的功能。

### 動態顯示與隱藏

角色切換時，以既有 `tab_index_by_key` 找到 Profile 內的 TAB，呼叫 `QTabWidget.setTabVisible(index, visible)` 套用角色矩陣。

必須保留以下性質：

- 隱藏的 TAB 不顯示標籤，也不占 TAB 列空間。
- 其右側可見 TAB 自動向左遞補。
- TAB 物件與內容狀態保留。
- 既有 QTabWidget index、`tab_index_by_key`、`self.tabs` 與特殊頁索引不因角色切換而改變。

不得在執行期間以 `removeTab()`／`insertTab()` 實作角色切換，避免索引、頁面刷新及 HELP 對應錯位。現有啟動階段依 Profile 移除產品版本不包含的 TAB 的行為不在本次變更範圍。

## 主選單與登入流程

首頁主選單維持現有外觀與全部功能 icon，不隨角色隱藏。

使用者點擊主選單功能時：

1. 若目標 TAB 對目前角色可見，沿用既有流程開啟目標。
2. 若目標 TAB 對目前角色隱藏，不顯示額外訊息框，改為：
   - 記住原目標的功能 key。
   - 切到「資料庫設定」TAB。
   - 顯示既有密碼登入畫面。
   - 在登入畫面內說明需登入才能使用原目標功能。
3. 登入成功並重套 TAB 可見矩陣後：
   - 新角色可使用原目標時，自動開啟該 TAB。
   - 新角色仍不可使用原目標時，留在資料庫設定頁，不開啟隱藏 TAB。
4. 待處理目標在完成導向或確認仍無權限後清除，不得影響後續一般登入。

例如歸檔管理員從主選單點擊「操作紀錄」時，會被帶到設定登入頁；以歸檔管理員登入後仍留在設定頁，因為操作紀錄只對管理者顯示。

主選單關閉後若以 `blockSignals(True)` 或其他靜默方式切到設定頁，必須同步主視窗用來追蹤前一頁的狀態（目前為 `_prev_tab_index`）。否則使用者第一次離開設定頁時，既有設定排序未儲存提示與頁面刷新可能把錯誤頁面視為前一頁。

## 登出與角色變更

主動登出與閒置逾時登出均透過既有 `role_changed` 流程重套 TAB 可見矩陣。

若角色降低後目前 TAB 即將被隱藏，必須先切到「資料庫設定」登入頁，再隱藏不再可用的 TAB，避免主畫面停留在不可見頁面。若目前 TAB 對新角色仍可見，可保留目前頁面。

應避免角色切換期間觸發錯誤的未儲存切換提示或刷新隱藏頁面。既有各 TAB 的未儲存資料處理語意不變。

## HELP 與速查卡

現有 HELP 以 QTabWidget 固定 index 對應 Profile 的功能 key，再映射到完整版 HELP 內容頁。`setTabVisible()` 不改變內部 index，因此可見 TAB 在畫面上向左遞補後，HELP 仍應顯示該功能的正確內容。

設計限制：

- 角色切換不得重新壓縮或重建 index mapping。
- HELP 不以「畫面上第幾個可見 TAB」作為內容索引。
- 被隱藏的 TAB 無法直接被選取，因此不會從該頁開啟 HELP。
- HELP 內容與現有完整版固定內容 ID 維持不變。
- 速查卡仍可介紹完整功能，與保留完整首頁主選單的設計一致。

共用 HELP 與速查卡須補充：

- 三種角色各自可見的 TAB。
- 設定 TAB 永遠保留並兼作登入入口。
- 從主選單選擇目前隱藏的功能時，系統會直接導向設定登入頁。
- 登入後只有新角色可使用的目標才會自動開啟。

不得改動既有 HELP 的固定內容 ID 或依可見順序重新編號。

## 錯誤與邊界處理

- 找不到主選單要求的功能 key：沿用現有安全處理，不得誤開其他 TAB。
- Profile 不包含目標功能：不得因角色登入而建立或顯示該功能。
- 登入失敗：留在設定登入頁並保留既有登入錯誤呈現；不得顯示隱藏 TAB。
- 登入成功但角色不足：留在設定頁並清除待處理目標。
- 一般使用者永遠看得到資料庫設定 TAB，以確保登入入口存在。

## 測試與驗收

### 自動化測試

- 驗證完整版三種角色的 11 項可見矩陣。
- 驗證一般使用者有 9 個可見 TAB，且包含交辦單發文、敘獎發文與資料庫設定。
- 驗證歸檔管理員有 10 個可見 TAB，只隱藏操作紀錄。
- 驗證管理者可見全部 11 個 TAB。
- 驗證獨立版只在 Profile 原本包含的 TAB 內套用角色矩陣，不會顯示完整版專屬功能。
- 驗證角色切換前後固定 index 與 `tab_index_by_key` 不變。
- 驗證主選單點擊隱藏功能會導向設定登入頁，不會選取隱藏 TAB。
- 驗證登入成功後只在新角色有權限時續接原目標。
- 驗證主動登出與閒置登出時，若目前頁面將被隱藏，會先回到設定登入頁。
- 驗證靜默導向設定頁時 `_prev_tab_index` 同步，第一次離開設定頁仍會正確執行既有未儲存處理。
- 擴充 HELP smoke test：對三種角色逐一確認每個可見 TAB 的 HELP key／內容頁仍正確。
- 驗證 HELP／QUICKSTART 的角色矩陣與登入導向說明存在，且既有固定內容 ID 未重新編號。

### GUI 上機驗收

在 Windows 125% 顯示縮放、全域 14pt 字體下驗證：

- 隱藏 TAB 後不留空白位置，剩餘 TAB 確實向左遞補。
- 一般使用者與歸檔管理員的 TAB 列擁擠程度獲得改善。
- 主選單 icon 外觀與排列不變。
- 點擊受限功能不跳訊息框，而是直接進入設定登入頁。
- 登入畫面正確說明原本要求的功能。
- 登入後自動續接與權限不足時留在設定頁的行為正確。
- HELP 顯示內容與目前可見 TAB 相符。
- 共用 HELP 與速查卡能讓使用者理解不同角色看見的 TAB，以及受限主選單入口為何導向設定登入。
